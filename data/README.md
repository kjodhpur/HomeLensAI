# Data

**Nothing in `raw/`, `processed/`, `cache/` or `annotation/` is committed** (see `.gitignore`): the Yelp Open Dataset licence does not allow redistributing the data.
Each teammate downloads it once.

## Where to put the Yelp download — no unzipping needed
Copy the **zip files exactly as downloaded** into `data/raw/` (inside your clone of this repo):

```
HomeLensAI/
└── data/
    └── raw/
        ├── <first>.zip
        └── <second>.zip        ← any names; any folder layout inside; may contain a .tar or another .zip
```

The notebook searches every `.zip`, `.tar`, `.tar.gz` and `.tgz` in `data/raw/` (and archives nested inside them) for `yelp_academic_dataset_business.json` and
`yelp_academic_dataset_review.json`, and **streams them straight out of the archive** — nothing is unpacked, so it works even when your OS refuses to unzip the ~5 GB file
(common: macOS Archive Utility "Error 79 / 22", Windows path-length limits). Plain, already-unzipped JSON files in `data/raw/` work too.

On the first run it keeps only Tucson, AZ home-service businesses and writes `data/raw/HomeLens_Yelp_HomeServices.csv` (≈ a few minutes); later runs reuse that CSV.
The Milestone 1 extract had 23,685 reviews / 1,403 businesses; expect a similar ballpark before the "true service provider" filter in Section 3 (the notebook prints the exact counts).

Where to get the files if you do not have them yet: <https://business.yelp.com/data/resources/open-dataset/> or <https://www.kaggle.com/datasets/yelp-dataset/yelp-dataset>.

### Already have the Milestone 1 extract?
Put `HomeLens_Yelp_HomeServices.csv` in `data/raw/` instead. The notebook accepts any of these column spellings (`COLUMN_ALIASES`, Section 3): `review_id, business_id, text, date, categories`, the review-level star
column (`review_stars`, `stars`, or `stars_x`/`stars_y` after a merge), and optionally `name`/`business_name`, `city`, `state`, `business_stars`, `review_count`.

## No data at all?
`data/sample/sample_reviews.csv` is a **synthetic** dataset (40 fake providers, ~1,170 reviews) generated by `scripts/make_sample_data.py`. The notebook falls back to it automatically and prints a
**DEMO MODE** banner. It exists so the pipeline, the API and the web app can be built and tested without the real data. Its numbers are *not* results.

## Folders
| Path | Content | In git? |
|---|---|---|
| `data/raw/` | Yelp zips / raw JSON / extract CSV | no |
| `data/sample/` | synthetic reviews + `outputs/` (JSON the pipeline produced from them) | **yes** |
| `data/processed/` | JSON artifacts from the **real** run (`provider_risk.json`, `summary.json`, `aspect_lexicon.json`) | no |
| `data/cache/` | cached DistilBERT predictions + aspect extraction | no |
| `data/annotation/` | the aspect-precision audit CSV the team labels | no |

## Streamlit app artifacts
The Streamlit app (`streamlit_app.py`) reads only the aggregated, anonymized tables in `artifacts/` and never the raw data.
With `data/raw/HomeLens_Yelp_HomeServices.csv` in place, rebuild them with:

```bash
python scripts/build_artifacts.py --data data/raw/HomeLens_Yelp_HomeServices.csv
```
